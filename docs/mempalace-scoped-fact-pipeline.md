# Scoped automatic useful facts

The opt-in `automatic_config` on an exact trusted memory route enables a
Hermes-native durable outbox. This is a local, same-UID integration; it is **not**
the separately hardened cross-UID MemPalace extraction daemon.

Only typed original authenticated Telegram text/captions are eligible. Each
batch constituent has an independent source event. Passive observations enter
the inbox atomically as context-only and cannot create jobs or replies. A bot
response need not complete for a user's assertion to be eligible. Forwarded,
quoted/control, generated-media, unknown-author and unknown-topic inputs are
excluded. Detected credentials are rejected before enqueue/provider calls and
again at direct memory writes; harmless codewords remain supported. Detection
is conservative and is not a guarantee that every possible secret is recognized.

Original evidence, extracted output, result and current-fact ledger are sealed.
The worker rechecks current gateway authorization, exact profile/topic route and
memory policy before extraction and each mutation. Revoked jobs do not regain
old permissions. Temporary failures retain cached extraction and bounded retries;
an inbox admission independently survives a failure to open the outbox. Status
and errors are metadata-only. Inspect the worker status and blocked/retry counts.

Recovery records a sealed per-admission disposition and advances past permanent
malformed, tampered, revoked or conflicting inputs. A transient database/config
read failure leaves the cursor retryable. Two independently sealed original
admissions with the exact same source/actor/purpose/ACL but different trusted
received timestamps become explicit internal admission revisions. This is not
proof of a Telegram edit. The first job ID and all original evidence are retained;
the same exact receipt always resolves to the same job. Same-text reaffirmations
reuse only sealed, revalidated output and update source chronology. Equal-time
contradictions are blocked, including across distinct source IDs.

Extractor JSON and subject.property keys share one deterministic schema. A
validation failure receives at most three total validation attempts, preserving
sealed reason/code/output-hash diagnostics but never raw rejected model output.
The source-substring check stays strict; unsupported results can finish without
facts or remain blocked, never falsely acknowledged as a save. Administrative
reprocessing accepts an exact signed single-use target plan, retains original
failures/evidence and does not reset the retry budget.

The existing configured no-tools model selects up to three useful assertions.
Canonical stored content is an exact supporting source clause, not a generated
paraphrase. Subject-qualified property keys are isolated by author and Wing.
Corrections replace the current fact page; retractions replace it with a tombstone.
Source timestamp and provenance remain attached. Explicit memory tools process
the same source-bound operation; queued/partial/zero-fact outcomes are not a
successful save. MiniLM embeddings remain local. New facts are indexed pages;
the historical knowledge graph is not a complete index of newly learned facts.

Nutrition specialists receive a narrowly registered `specialist_nutrition`
capability for `private.<principal>.nutrition`, independent of group/profile.
The actual group source is retained. Backend actor/owner/destination/grant checks
are mandatory; the group parent cannot select this Wing. Existing curated
participant files are migrated verbatim with owner/source evidence and retained.
An original public assertion may be shared group memory and separately useful
private nutrition context; private files, recalled content and specialist output
never become group extraction sources.

The one-turn private-disclosure route stays read-only: no capture, sync, update,
delete or carryover into later turns. Legacy extraction is explicitly retired
on migrated profiles; the remaining default route admits only positively proven
unmigrated private user messages.

Rollout requires independent predeploy approval. Rollback restores exact owned
code/config targets after drift checks; it never restores database snapshots or
deletes current facts, outbox, seal key, migration evidence or retained files.
